# 电视声音基线诊断

更新于 2026-10-25。此文记录已取得的诊断证据与验证边界。本地测试音已通过用户听感确认；远程音频尚未确认可听，也没有实现电脑／电视独占声音切换。

## 已取得的证据

- Windows 端报告：Telegram 使用默认 Realtek Digital Output；输出设备音量 14%、应用会话音量 80%，均未静音。RustDesk 日志选择同名默认输出进行 48 kHz、双声道 F32 回环采集，未发现采集初始化错误。端点 GUID 尚未由日志证实。
- 电视已有日志显示：RustDesk 解码后的 S16LE PCM 非零，播放器提交给系统回调的 PCM 同样非零。输入非零采样中位峰值约 150、RMS 56；输出约 179、RMS 72，输出观察到的最大峰值 448，约 −37.3 dBFS。该统计是间隔抽样，不代表整个音频的最大值。
- Rust Opus 解码代码按样本数将 float 乘以 32767、转为小端 int16；C++ 使用相同的 48 kHz、双声道、S16LE 配置，缓冲区按字节复制。代码审查未发现重复音量缩放或明显的格式错配。
- 音频服务快照中，屏间和华为视频均指向 `DP_speaker`，格式同为 S16LE／双声道／48 kHz。系统策略显示的 HDMI/type27 与此路由对应，单凭该设备名称不能认定输出错误。
- 最近只读快照中，屏间播放器处于 PAUSED；系统与应用音量因子、duck 因子均为 1，未静音。该快照不能说明前一次播放期间的实际声音状态。

Windows 与电视的电平采样并非同一时刻、同一段音频，不能直接相除计算链路衰减。播放器回调收到非零数据也不能证明扬声器已发声。目前没有证据支持安装虚拟声卡或直接放大远程 PCM。

## 本地测试声音

「输入设备测试」右上角新增「测试声音」。仅由用户点击触发，播放 1.5 秒的 440 Hz／660 Hz 混合音，包含 80 ms 渐入渐出，峰值不超过满量程的 0.15。

测试采用 AudioKit 的 MUSIC、48 kHz、双声道、S16LE 播放路径，不依赖电脑、网络或 RustDesk，不修改系统音量，不采集麦克风、不录音。播放期间按钮显示「播放中…」，结束后释放播放器。离开页面会取消；重复点击不创建重叠播放器。

该测试使用 ArkTS AudioRenderer，其系统格式和用途与远程 OHAudio 播放器一致，但并不覆盖原生回调、远程缓冲队列或 Opus 解码实现。因此测试音有声只能建立系统输出可听基线，不能单独证明远程播放路径正常。

## 下一步判定

1. 本地测试音也无声：核查当时系统输出、应用音量与实际播放进度；保持原音量，先排查系统输出路径。
2. 本地测试音有声、远程仍无声：用同一确定有声素材同时读取电脑输出峰值、电视 PCM 电平，以及音频服务读写位置的增长，进一步区分远程输入过低和播放消费异常。
3. 电视远程声音确认可听后，才进行电脑扬声器静音对照，并保存、恢复原设备和音量。现阶段不能承诺扬声器静音后回环采集仍有声。

## 验证状态

本地模拟播放器已检查波形长度、峰值、左右声道一致性、分段／部分写入、重复启动、创建／写入／排空期间取消、写入失败和资源释放。9 项可重复音频测试通过，签名 HAP 已构建并安装。用户实机点击「测试声音」后确认能听到；远程 RustDesk 声音仍需单独验证。
