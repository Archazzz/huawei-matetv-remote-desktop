# 给 Windows 端 Codex 的协作提示词

请继续排查这台已配置 RustDesk 1.5.0 的 Windows 电脑。电视端已能看到画面、控制双屏，但播放 Telegram 视频仍有掉帧，电视没有声音。当前保持电脑输出未静音，不要把已有无声误判为静音导致。

先做只读诊断，不重装驱动、不放宽防火墙，不修改音量或静音：

1. 列出显卡型号、驱动版本；核实 RustDesk 的硬件编码设置，以及当前电视会话实际选择的编码器。电视曾收到 5120×1440 VP9，码率约 50–80 Mbps，使用软件解码。请从 RustDesk 官方能力和本机日志确认 H.264/H.265 编码是否可用、为何回退 VP9；不能只凭显卡型号认定已启用。
2. 用户播放带声音的视频时，读取 Windows 默认多媒体／通信输出设备、Telegram 当前实际音频会话所在的输出设备、各设备静音/音量及峰值电平。默认输出曾是 Realtek Digital Output，未静音、14%，用户能听到书房音响。
3. 核实 RustDesk 当前用于采集的音频设备设置，以及当前会话音频权限。查日志是否有回环采集、设备选择或初始化失败。仅报告设备名、错误码和峰值数字，不录制或导出音频，不输出密码、令牌或聊天内容。
4. 对比 Telegram 实际播放端点和 RustDesk 采集端点，给出是否一致的证据；若无法确定，请明确缺少哪条证据。
5. 保留已创建的 AudioEndpointControl.ps1 及原状态记录。本轮先不执行 SetMute；电视端确认基线有声后，再做明确静音与恢复的对照。

回传简短结果：GPU/驱动、硬件编码可用性与当前编码、两个音频端点是否一致、播放时峰值是否非零、下一步最小改动。任何配置修正先说明具体字段与原值，再由用户决定执行。
